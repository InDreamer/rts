Final Contract · Source / KB / Snapshot / Runtime

最终方案固定为一条可生成、可签核、可服务的文件契约。

后续生成器就按这套结构输出：source 先变成证据入口，规则写进 YAML/Markdown KB，发布前冻结成 canonical JSON/JSONL snapshot，再生成不可变 runtime projection。搜索、HTML 和 LLM context 都只能从已发布内容派生。

下次生成 KB

必须产出 `metadata.yaml`、`rules/*.yaml`、`lookups/*.yaml`、`helpers/*.yaml`、`evidence/`、`review/` 和 `reports/`。

下次发布 projection

必须先有 signed snapshot，再生成 `runtime-store/releases/{release_id}/`，release id 不允许原地覆盖。

服务读取边界

RTS runtime 默认只读 active runtime projection，不读 KB 草稿、source bundle 或 unsigned snapshot。

固定链路

五层各自负责一件事，不能互相越界。

这不是“选 JSON 还是 YAML”的问题，而是把写作、证据、签核、服务读取和派生展示分开。每层的文件格式跟职责绑定，后续实现和生成器都按这个契约走。

0

Source

保存 locator、revision、hash、权限和抽取说明，不保存最终规则结论。

1

KB

规则、lookup、helper、evidence、review 的可维护结构化工作区。

1.5

Snapshot

把 KB 规范化成 write-once JSON/JSONL，冻结 hash 和签核。

2

Runtime

服务实际读取的 immutable release package。

3

Derived

索引、HTML、报告和 LLM context，只做定位、展示和装箱。

生成顺序

从 source 到 projection，每一步都有固定产物。

步骤必须输出拒绝条件
0. 选择 identity/scope`pack_id`、`source_bundle_id`、`scope`、`canonical_revision`scope 不唯一；pack id 冲突
1. Source intake`source-manifest.yaml`、`source-index.yaml`、`extraction-notes.md`没有 stable locator、source revision、hash 或权限状态
2. Structured KB`metadata.yaml`、`rules/*.yaml`、`lookups/*.yaml`、`helpers/*.yaml`、`evidence/`、`review/`、`reports/`object id 不稳定；ref 无法解析；scope 冲突
3. Snapshot + signoff`snapshot-manifest.json`、`objects.jsonl`、`signoff.json`、`projection-map.jsonl`hash 不可复现；signoff 未覆盖 projected objects
4. Runtime projection`runtime-store/releases/{release_id}/...`缺 snapshot id/hash/signoff id；release id 已存在；L2 hash 不匹配
5. Derived outputs`index-artifacts/`、HTML/Markdown views、LLM context items派生层新增业务断言；context 缺 uri/hash/role/trace

Source 层负责回答“这条规则从哪里来”。它保存 source locator、revision、hash、权限和抽取说明，但不能被 runtime service 当 truth 读取。

Layer 1

Structured KB authoring package：规则的工作真相。

KB 用 YAML/Markdown，是因为它要长期被 agent 和 reviewer 维护。它不是最终签核物，但它是进入签核前的 governed working truth。

KB 包必须长这样kb/{pack_id}/

  metadata.yaml
  README.md
  rules/{rule_id}.yaml
  lookups/{lookup_id}.yaml
  helpers/{helper_id}.yaml
  evidence/evidence-index.yaml
  review/review-index.yaml
  reports/extraction-report.md
  reports/review-checklist.md
  reports/closure-check.md
  attachments/                 # optional
  snapshots/                   # generated after validation and signoff
文件固定格式必须包含
`metadata.yaml`YAMLpack id、status、canonical revision、source bundle、scope、object counts、indexes、release eligibility
`rules/*.yaml`YAMLid、object type、status、revision、scope、source anchors、evidence refs、inputs、logic、target、dependencies、examples
`lookups/*.yaml`YAML + CSV/TSVkey columns、normalization、return fields、fallback/missing policy、data or attachment ref
`helpers/*.yaml`YAMLinputs、outputs、logic pipeline、consumers、dependencies、evidence refs
`evidence/evidence-index.yaml`YAMLevidence id、object refs、source refs、locator summary、quote/summary、confidence、permission/redaction state
`review/review-index.yaml`YAMLdecision id、object refs、decision type、status、question、decision、decided by/at、evidence refs、remaining risk
`reports/*.md`Markdown抽取报告、review checklist、closure check；只能说明，不能保存唯一 truth

Layer 1.5

Snapshot 把 YAML/Markdown KB 规范化成 deterministic JSON/JSONL。签核冻结的是对象语义、hash、review decision 和 human confirmation，不是 YAML 的空白和注释。

  change-log.jsonl
  signoff.json
  projection-map.jsonl

`objects.jsonl`规范化对象语义object id/type、scope、revision、content hash、source anchors、evidence refs、dependencies、release eligibility

Layer 2

Runtime projection 从 signed snapshot 生成，release 目录不可原地覆盖。API、MCP、managed LLM、index builder 都应该通过它或服务工具读取事实。

文件必须包含边界
`release-manifest.json`release id、schema version、release tier、canonical snapshot id/hash、signoff id、content hash summaryproduction 不能只写 canonical revision
`object-manifest.jsonl`uri、object id/type、scope id、L2 ref/hash、snapshot object id/hash、truth role、governance refs每个 L2 都要能回溯 snapshot

Publisher 必须做检查点

Reference resolutionsource locator、evidence refs、review refs、dependency refs 全部可解析

Signoff coverage`signoff.json` 覆盖所有 projected objects
Projection proof`projection-map.jsonl` 覆盖所有 runtime L2 objects
Smoke tests证明服务能读 L2、验证 hash、走 dependency、组装 answer、写 trace

发布门槛

production release 的拒绝条件要写死。

必须接受前满足

source locator 可追溯；KB 校验通过；snapshot hash 可复现；signoff 覆盖所有 projected objects；blocking issues 为 0；runtime manifest 引用 snapshot id/hash/signoff id；projection-map 覆盖所有 L2；service smoke test 通过。

必须拒绝

process-only signoff、缺 source bundle、缺 snapshot id/hash、缺 signoff id、unsigned snapshot、L2 无 snapshot object hash、runtime 内容无声明 transform 就偏离 snapshot、服务默认读 KB 或 source。

文件选择

每类文件用什么格式已经固定。

文件/目录固定格式原因
`sources/**/source-manifest.yaml`、`source-index.yaml`YAMLlocator、权限、revision 需要易读易审
`kb/**/metadata.yaml`、`rules/*.yaml`、`lookups/*.yaml`、`helpers/*.yaml`YAML规则 authoring 需要稳定 diff 和可维护结构
`kb/**/reports/*.md`Markdown报告和 checklist 是说明层，不是 truth owner
`kb/**/snapshots/*.json`、`*.jsonl`JSON / JSONL签核、hash、line records 需要 deterministic schema
`runtime-store/**/manifest.json`、`l2/**/*.json`JSONservice truth object 和 manifest
`runtime-store/**/navigation/*.jsonl`、`dependencies/*.jsonl`JSONL图、视图、索引 friendly
`index-artifacts/opensearch-docs.jsonl`、`lucene/`JSONL / Lucene binary可移植搜索导出和本地重建索引
`html/*.html`HTML只做展示和 review，不进入 truth 链

最终口径

以后从 source 到 runtime projection，就按这份契约生成。

Source 固定成证据入口；KB 固定成 YAML/Markdown authoring package；snapshot 固定成 write-once canonical JSON/JSONL signoff freeze；runtime projection 固定成 immutable JSON/JSONL service release；index、HTML、LLM context 只从 projection 或 release-bound governance summaries 派生。
