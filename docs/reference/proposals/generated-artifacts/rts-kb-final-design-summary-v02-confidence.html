2. 最终前提

人不直接维护 KB 文件；人通过 AI 的解释和问题确认参与审核。 Medium

这是本轮讨论的关键修正。它支撑“canonical KB 用 JSON”的判断；如果以后改成人直接编辑 KB，则文件格式需要重新评估。

AI 审核解释schema / evidence / conflict
→
人对话确认确认 / 拒绝 / 补充
→
AI 修改复审change log + hash
→
Signofffreeze snapshot

3. 文件格式最终判断

格式定位Confidence复核备注
JSONCanonical KB truth：pack/object/signoff。High在 AI-mediated review 前提下成立；schema/hash/export 最稳定。
JSONLAppend-only 辅助层：edges/evidence-index/change-log/confirmation-log。High不面向人工手写；应配套 HTML/MD pretty view。
Markdown报告、解释、README、closure note。High不适合作 canonical truth；可作为人类说明层。
HTML视觉审核、问题解释、结构展示。High只能是派生 view，不进入 truth。
YAML人直接维护 KB 时可重新考虑。Medium当前不选 canonical；如果人工裸眼编辑成为主流程，需重审。
DB后续 derived store / query backend。High不作为 v0.1 canonical truth。

6. Source / Evidence 边界

不默认保存 source_message_record High

KB 不复制 codebase、文档库或聊天历史。source 通过 evidence locator 被引用。

Evidence 必须有 source locator High

至少包含 source_type、稳定 locator、source revision/snapshot、quote/summary、redaction/permission 状态。

{
  "evidence_id": "ev_001",
  "source_type": "codebase",
  "locator": {
    "repo": "tradition-transformer",
    "commit": "abc123",
    "path": "src/.../StaticMappingLookupCore.java",
    "symbol": "getCutoffWithFallback",
    "line_range": [120, 168]
  },
  "quote_or_summary": "Reverse pair fallback is used when forward lookup is blank.",
  "redaction_state": "not_required"
}

8. Git 与 revision / content_hash / signoff snapshot

结论Confidence说明
Git 不能替代 signoff snapshot。HighGit 是 repo-level；signoff 是 domain-level，冻结 object_id + revision + content_hash 集合。
revision 可以轻量保留。Medium如果要极简，可讨论只保留 content_hash + snapshot，但 Codex 建议 revision 能提升对象级审计。
content_hash 必须保留。High用于证明 signoff 后对象内容没有漂移。
