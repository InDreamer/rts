Portable Package · Company Computer Ready

把 RTS repo 上传到公司电脑后，就按这条链路继续。

这个工作包包含最终契约、三个 portable skills、公司电脑执行清单和 pending 边界。第一阶段只做到 source profile、KB pack、KB review、ask-user-questions，不直接宣称 production runtime projection。

Company Computer Steps

上传后按清单跑，不需要重新翻对话。

先读

`docs/company-computer-kb-workflow-checklist-zh.md`，再读 `skills/AGENTS.md`。

第一条 prompt

让 agent 使用 `skills/rts-workflow-source-profiler`，只读公司 source，输出 `sources/{source_bundle_id}/`。

不要做

不改公司源码、不复制长源码、不绕过 source profile、不直接 production signoff。

完成线

第一阶段以 KB review 和 blocking user questions 闭合为止。

公司电脑第一条 agent prompt
Use the skill at rts/skills/rts-workflow-source-profiler.

Read the company source repo as read-only. Build an RTS source profile for the full workflow from gRPC inbound FpML/XML to Solace outbound SCBML/XML.

Do not modify source code. Do not copy long source excerpts. Produce only locators, hashes, summaries, workflow map, evidence candidates, and unresolved questions.

Output under rts/sources/{source_bundle_id}/:
- source-manifest.yaml
- source-index.yaml
- workflow-map.yaml
- extraction-notes.md
- unresolved-questions.yaml

Pending Boundary

snapshot/runtime publisher 先不冒充 production。

Snapshot skeleton

可以在 KB review blocking 为 0 后生成 skeleton，但 production signoff 需要 canonical hash 和 validator。

Runtime skeleton

可以从 snapshot skeleton 生成 demo runtime 形状，但不能宣布 production service truth，也不能默认供业务调用方消费。

Production publisher

必须等待 deterministic validator、hash、signoff、projection-map 和 service smoke tests。
