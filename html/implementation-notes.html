Implementation Notes

这个页面记录本次整理过程中对规格的解释方式。它不是 RTS confirmed baseline；字段契约、读写边界和发布规则仍以 confirmed Markdown 文档为准。

Design Decisions

设计决策

01

采用五层主链路

所有入口统一为 source intake -> structured KB -> canonical signoff snapshot -> runtime projection -> derived outputs。旧的 KB/runtime/index 三层表达保留为子链路，不再作为完整生成路线。

02

保留长 leaf 文档

`kb-runtime-index-layer-standard-zh.md` 和 final contract 很长，但它们分别覆盖单一标准面和单一最终契约面。当前只处理校验警告，不为压行数强拆文档。

03

HTML 是展示层

HTML 输出用于阅读、导航和核对，不进入 truth 链。搜索索引和页面摘要只指向来源，不承担 service truth。

04

Implementation notes 独立

本页记录本次整理的解释和开放问题，不加入 `docs/catalog.yaml`，避免被 future agent 当作 confirmed authority。

Deviations

有意偏离或补充

没有把所有历史 HTML 重生成

当前站点是静态 HTML 与 Markdown 转换页混合形态，没有统一生成脚本。本次只同步活跃入口页、来源库、搜索索引和新增 notes，避免误改历史展示页。

未把 notes 写入 confirmed docs

用户要求的是实现备注，不是新的系统契约。因此本页作为交付说明留在 `html/`，不覆盖 confirmed Markdown。

只清理 active 口径

`docs/archive/` 仍保留历史措辞。archive 的职责是考古，不参与 active baseline，因此没有为了统一新口径改写历史材料。

Tradeoffs

取舍

选择没有选什么原因
按 confirmed final contract 统一口径重新设计文档树当前 PD-3 校验已经 0 error，问题主要是入口措辞和展示面滞后。
把 snapshot 写进读者主线继续只说 KB -> projection新生产包必须通过 canonical signoff snapshot；省略它会误导 publisher 和 review 流程。
保留 demo/skeleton 边界把 runtime skeleton 描述成可生产服务真相deterministic publisher、canonical hash、signoff 和 smoke test 完成前不能宣称 production service truth。
用现有 HTML 风格补页重做视觉系统用户关注的是口径统一和最终 HTML 输出，现有样式足够承载本次 notes。

Open Questions

待确认项

01

Publisher 实现时间

canonical snapshot publisher、production provenance gate 和 write-once release gate 仍是实现待办，不在本次文档清理中补代码。

02

公司电脑 source 权限

真实 source scanning、DB/Excel/XSLT/Java/UT 读取权限需要在公司电脑上确认。

03

Production actor 标识

demo snapshot 可使用 role/process identity；production signoff 需要真实 actor 或批准 workflow identity。

04

HTML 自动生成策略

当前没有统一 HTML 生成脚本。后续如果 HTML 会频繁发布，建议补一个从 catalog/Markdown 生成来源页和搜索索引的脚本。
